# Step 0 notes: the spine

Step 0 builds what every later step calls into: run config with two live locks (`dry_run: false` in the run config and `SWARM_LIVE` in the environment), a price table verified against the live pricing page on 2026-11-06, a cost meter that appends one JSON line per call to `runs/<run>/usage.jsonl` and raises `BudgetExceeded` once a run passes its cap, one pure request builder that places the prompt-cache markers, the live `AnthropicClient` and the dry-run `ScriptedClient` (both go through that builder and the meter), a generic tool loop, and the `swarm` CLI. **Borrowed** from the SALT-NLP reference repo: an append-only per-call usage journal tagged with episode, agent and phase; cache markers added to a *copy* of the outgoing request so they never pile up in stored history, with assistant turns (thinking blocks included) replayed unchanged; and the split between retryable errors (429, 5xx, network) and fatal ones (other 4xx), with capped, jittered exponential backoff that respects `retry-after`. **Done differently:** no LiteLLM, just the official `anthropic` SDK, with one provider per run and the provider written on every usage line, so AgentRouter can arrive as its own step; our own verified prices instead of LiteLLM's cost map, plus a hard USD cap, which the reference repo does not have; tenacity as the only retry layer, with the SDK's built-in retries turned off; dry-run by default through a scripted client; stdlib logging with rich instead of `print()`; and empty or refused responses are recorded, never retried, so retries cannot bias the sample. The current API also forced some choices: `temperature` is never sent (SDK 2.x rejects it), each model gets its thinking-off switch (Sonnet 5.5 `between_tools`, Haiku 5.5 `disabled`; Opus 5.5 cannot turn thinking off, a documented deviation for spot checks), a forced `tool_choice` is refused up front on Sonnet and Opus 5.5, and refusal fallbacks are off because they would re-run a declined request on a different model. **Open questions:** (1) a 1-hour cache write costs 2x input against 1.25x for 5 minutes and only pays off when the same prefix is re-read 5–60 minutes later, but turns inside a tool loop are seconds apart, so let's measure both TTLs in the step 2 calibration; (2) step 3 cannot force the verdict tool on Sonnet 5.5, so what should happen when an agent ends its turn without calling it: re-prompt once, or record a missing verdict?; (3) step 4's memory drops task traces, which counts as editing history, and on accounts created after 2026-08-31 the API rejects a replayed thinking block after such an edit, so kept turns will need their thinking blocks stripped (Sonnet's `between_tools` progress notes can produce them); (4) only our direct dependencies are pinned, so should we `pip freeze` a full lock file for the public repo?; (5) the four live tests (cache check and tool round-trip, on Haiku and Sonnet, under $0.05 in total) have not run yet: they need `export SWARM_LIVE=1` and your "go live".
